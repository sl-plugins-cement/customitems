# CustomItems 协作者入门

CustomItems 是共享 LabAPI 工具库，负责物品身份登记、持有模型等通用机制。
它不自动创建物品玩法，也不是独立加载的玩法插件。`ServerKeybinds.dll` 是必需依赖。

## 先学身份，再学模型

在 [Cement 示例仓库](https://github.com/sl-plugins-cement/scpsl-plugin-examples) 按 `docs/start-here.md` 构建。
`examples/Foundations` 用一个原版硬币作为载体：只有被登记的序列号才是“教学硬币”。
不要用 `ItemType.Coin` 判断“这是我的自定义物品”，否则会影响普通硬币。

```csharp
enum Kind { TrainingCoin }
var items = new ItemRegistry<Kind>("MyPlugin");
// 发放成功后登记；item 是 player.AddItem 返回的非空物品。
items.TrackGranted(item.Serial, Kind.TrainingCoin, player.UserId, "grant");
// 业务事件中检查当前序列号。
if (items.IsKind(item.Serial, Kind.TrainingCoin)) { /* 处理自己的物品 */ }
// 按实际发生的转移记录；这些调用不会替你执行原生丢弃/拾取。
items.Drop(item.Serial, player.UserId, "drop");
items.Transfer(item.Serial, nextPlayer.UserId, "pickup");
// 世界中的物品已销毁时：
items.Destroy(item.Serial, "destroyed");
// 回合重置与插件关闭时：
items.Clear();
```

这是调用顺序说明，不是可整段执行的发放/转交实现。完整事件接线见教学插件。
`Untrack` 只撤销登记；`Destroy` 记录销毁并撤销登记，也不会替你删除世界对象。
事件接口依据为 `src/ItemRegistry.cs` 与 `src/TrackedItemLifecycle.cs`。

## 生命周期职责

- 调用方决定玩法、冷却、权限、持有者与物品转换规则；库不替你验证业务状态机。
- 丢弃/拾取保留序列号身份；冷却放在序列号上可以防止通过转交重置。
- 检查发放是否成功，覆盖背包满、死亡、断线、清背包、销毁、回合结束和卸载。
- 教学示例定期核对原生物品集合；生产插件应设计集中、低开销的生命周期管理。
- 需要自定义模型时再使用 `HeldMeshManager`；脱手、死亡、角色变化、断线和卸载都必须隐藏/清理。
- `HideAndReplace` 会引发强制空手状态；按 API 参考处理 `AbsorbForcedNone`，不要把它当成普通脱手。

## 从干净环境构建

先构建兼容的 ServerKeybinds，显式传入产物路径：

```powershell
dotnet build CustomItems.csproj -c Release -p:SCP_SL_MANAGED='D:\Servers\SCPSL\SCPSL_Data\Managed' -p:ServerKeybindsPath='D:\Cement\ServerKeybinds\bin\Release\net48\ServerKeybinds.dll' -p:DeployToLocalServer=false
```

输出为 `bin/Release/net48/CustomItems.dll`。不传 `ServerKeybindsPath` 时兼容原有本机 LabAPI 全局依赖目录；新协作者优先使用上面的显式路径或示例仓库脚本。
安装时两库都放到 LabAPI `dependencies/global`，消费插件放到测试端口的 `plugins`。替换后重启。

## 如何提交修改

每项任务开分支；共享元仓库使用独立 worktree。PR 用中文说明 API 影响、调用方、生命周期边界与验证结果。
公开接口保持兼容；同一 API 主版本内也应通过提交号确定依赖，不假设任意 API 2 DLL 都有新增类型。
构建成功不代表模型显示正确；模型变化必须附真实客户端观察结果。未验证项明确写出。
不要提交玩家资料、模型缓存、游戏 DLL 或未获授权的素材；生产部署由指定维护者执行。
